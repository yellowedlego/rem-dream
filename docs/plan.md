# 꿈(REM) 시스템 동아리 활동 기획서

Nov 4, 2026 · @노란색레고

## 요약

대화를 기억 노드로 쌓다가, '잠'(REM)을 시키면 AI가 기억을 다시 훑어 스스로 인격과 규칙을 고치는 모습을 보여 주는 전시용 AI 하네스예요. 관람객은 하루 이야기를 쓰거나 잠깐 채팅한 뒤, AI가 꿈꾸는 과정과 깨어난 뒤 달라진 답을 눈으로 봐요.

활동 목적은 세 가지예요.

- 뇌과학의 수면 중 기억 재구성을 AI 구조로 옮겨 보며 두 분야의 공통점과 차이를 설명할 수 있게 하기
- Claude Code로 실제 동작하는 프로그램을 만들어 축제에서 학생들이 체험하게 하기
- 모둠원이 REM 모드를 하나씩 직접 설계해 붙일 수 있는 구조로 만들어, 지식이 적어도 아이디어로 참여하게 하기

## 뇌과학 배경

잠은 한 덩어리가 아니라 NREM(깊은 잠)과 REM이 번갈아 오고, 둘이 기억에 하는 일이 달라요. 그래서 이 기획은 두 REM 모드를 실제 수면 단계에 하나씩 대응시켜요.

- 깊은 잠(NREM)에는 해마가 낮에 겪은 기억을 다시 재생하고, 그 내용이 대뇌피질로 옮겨지며 정리된다는 설명이 널리 받아들여져요(시스템 통합 이론).
- REM에는 서로 멀리 떨어진 기억들이 느슨하게 이어지고, 꿈이 뒤죽박죽인 이유도 여기서 찾는 연구가 많아요.
- 잠자는 동안 시상이 바깥 감각 입력을 막아요. 이 기획에서 'REM 중에는 대화가 멈춘다'가 여기에 해당해요.

| 뇌 | 이 시스템 | 비고 |
| --- | --- | --- |
| 시상(감각 중계) | 사용자 입력이 맥락으로 들어가는 통로 | REM 중에는 입력 차단 |
| 하루의 경험 | 노드 = {유저 입력, AI 답변} 한 쌍 | 채팅 한 번에 노드 하나 |
| 해마의 기억 재생(NREM) | 모드 1: 기억을 섞어 이어 가며 정리 | 앞 결과를 다음 처리에 맥락으로 넘김 |
| REM의 느슨한 연결 | 모드 2: 무작위 기억 두 개를 짝지어 연결 찾기 | 온도를 높여 엉뚱한 연결 유도 |
| 대뇌피질에 남는 변화(자아상·습관) | 시스템 프롬프트 수정 제안 | 적용은 사람이 승인 |

주의할 점이 두 가지 있어요. 첫째, 기억 재생은 주로 깊은 잠에서 일어난다고 보는 연구가 많아서, 모드 1을 'REM'이라고만 부르면 발표 때 지적받을 수 있어요. 둘째, 트랜스포머 어텐션은 뒤 토큰이 앞 토큰을 보는 방향이고, MLA는 KV 캐시를 줄이는 기법이에요. 연결 방식의 비유로 쓰지 않는 게 안전해요.

이 절의 뇌과학 내용은 Claude가 검색 없이 정리한 것이라 대략적인 설명이에요. 발표 자료에 넣기 전에 Diekelmann & Born(2010)의 수면과 기억 리뷰, Tononi & Cirelli의 시냅스 항상성 가설, REM과 창의적 연상에 관한 Cai 외(2009) 연구를 직접 찾아 확인하세요.

## 시스템 구조

채팅 한 번이 노드 하나가 되고, 잠들면 입력을 막은 채 노드를 다시 읽어 통찰과 인격 수정 제안을 만들어요. 제안은 사람이 승인할 때만 새 인격 버전이 돼요.

&#91;embedded content: 꿈 시스템 구조 · 깨어 있을 때 4단계, 잠잘 때 4단계, 승인 1회\]

승인한 제안만 새 버전으로 저장되고 다음 대화부터 대화 모델에 적용돼요. 거절한 제안은 디버그 화면에 기록으로만 남아요.

### 두 REM 모드

- 모드 1 (정리, 깊은 잠에 대응): 노드 순서를 섞어 하나씩 읽고, 앞에서 뽑은 통찰을 다음 노드를 읽을 때 맥락으로 넘겨요. C→c, (c+D)→d, (c,d+A)→a처럼 쌓여 마지막에 정리된 통찰이 나와요.
- 모드 2 (꿈, REM에 대응): 무작위로 노드 두 개를 짝지어 '둘의 연결고리'를 찾게 하고 온도를 높여요. 서로 상관없는 통찰 조각이 여러 개 나와요.
- 두 모드 모두 마지막에 통찰들을 모아 수정 제안 하나를 만들어요. 모드는 파일 하나에 하나씩 두어, 새 모드를 쉽게 추가할 수 있게 해요.

### 데이터 모양 (초안)

- 노드: 번호, 세션(채팅방), 순서, 시각, 유저 입력, AI 답변
- 통찰: 번호, 만든 모드, 근거 노드 번호들, 내용, 시각
- 인격 버전: 버전 번호, 시스템 프롬프트 전문, 근거 통찰 번호들, 승인 시각, 이전 버전 번호

## 화면 구성

화면은 전시 화면과 디버그 화면 두 개로 나누고, 둘 다 같은 핵심부의 기록을 읽기만 해요. 한쪽 화면이 망가져도 다른 쪽과 데이터는 멀쩡하게 남아요.

### 전시 화면 (관람객용)

- 가운데: 옵시디언처럼 떠 있는 원형 노드들. 순서를 잇는 선은 보여 주지 않아요.
- 노드를 누르면 오른쪽에 그 대화(유저 입력과 AI 답변)가 펼쳐져요.
- 아래: 입력창, 모델 선택창, '잠들기' 버튼.
- REM 중: 입력창이 잠기고 화면이 어두워지며, 지금 읽고 있는 노드가 빛나요. 새로 뽑힌 통찰은 원이 아닌 다른 도형(마름모 등)으로 나타나 관련 노드와 선으로 이어져요.
- 깨어난 뒤: '자는 동안 이렇게 바뀌려 해요' 카드에 시스템 프롬프트 수정 제안이 뜨고, 적용과 취소 버튼이 있어요.
- 애니메이션은 노드가 생길 때, REM 진행, 통찰 등장 세 군데에만 둬요.

### 디버그 화면 (우리용)

- 실시간 로그: 어떤 노드를 어느 모드로 처리했는지, 모델 요청과 응답 원문.
- 수치: 노드 수, 통찰 수, 요청별 토큰 수와 응답 시간, 오류 횟수, 남은 API 한도.
- 시스템 프롬프트 버전 목록과 버전끼리 달라진 부분 비교, 되돌리기.
- 조작: REM 강제 시작·중단, 모드와 온도 바꾸기, 전체 초기화.

두 화면은 같은 프로그램의 다른 주소로 열어요(예: 전시 화면 `/`, 디버그 화면 `/debug`). 전시용 컴퓨터에서는 디버그 주소를 열지 않으면 돼요.

## 기술 선택과 역할 분담

한 대의 노트북에서 웹페이지로 돌리는 구조로 시작해요. 전시 때 인터넷이 끊길 위험만 빼면 가장 단순하고, 화면과 서버를 한 프로젝트에 둘 수 있어요.

| 부분 | 추천 | 이유 |
| --- | --- | --- |
| 화면 | 웹페이지 (React + 노드 그래프 라이브러리) | 노드 그래프 예제가 많고 Claude Code가 잘 다룸 |
| 서버 | 같은 프로젝트 안의 작은 서버 | API 키를 화면 코드에 넣지 않으려고 |
| 저장 | 노드·통찰·프롬프트 버전을 파일(JSON)로 | 눈으로 열어 검수하기 쉬움 |
| 모델 | 제미나이 Flash 계열 | 싸고 빠름. 정확한 모델명은 시작할 때 확인 |
| 코드 관리 | GitHub 저장소 1개 | 모둠원 작업을 따로 받기 쉬움 |

구체적인 라이브러리 이름은 Claude Code가 Context7로 최신 문서를 확인하고 고르게 해요. 위 표는 방향이고, 확정은 첫 작업에서 해요.

### 누가 무엇을 하나

- 본인: 아이디어와 설계, 결과 검수, 다음에 고칠 점 정리
- Claude Code: 코드 작성, 실행, 화면 스크린샷 확인(Playwright)
- 모둠원: REM 모드 하나를 직접 설계. 코드가 아니라 '이 모드는 기억을 어떻게 고르고, 모델에게 뭐라고 시키는가'를 글로 쓰면, Claude Code가 모드 파일로 옮겨요.

### 모둠원이 아이디어를 붙이는 방법

깃 명령어는 몰라도 돼요. 커밋은 저장점, 브랜치는 본체를 건드리지 않는 실험용 갈래예요. 모둠원 아이디어는 브랜치 하나에서 만들고, 잘 되면 본체에 합쳐요. 이 과정은 Claude Code에게 '새 브랜치 만들어서 이 모드 추가해 줘'라고 말로 시키면 돼요.

## 개발 로드맵

오늘은 1단계까지, 즉 가짜 노드로 전시 화면을 띄우는 것이 목표예요. 각 단계는 '끝났다고 볼 기준'을 통과해야 다음으로 넘어가요. 축제 날짜가 정해지면 단계별 기간을 붙여요.

1. **약속 정하기 + 가짜 데이터 화면** — 노드·통찰·프롬프트 버전의 데이터 모양을 정하고, 가짜 노드 20개를 전시 화면에 띄워요.
   - 끝 기준: 노드를 누르면 대화가 펼쳐지고, 디버그 화면에 노드 목록이 보임
2. **채팅 연결** — 입력하면 제미나이가 답하고, 그 한 쌍이 노드로 저장돼 화면에 나타나요.
   - 끝 기준: 새로고침해도 노드가 남아 있음
3. **REM 모드 1 + 콘솔 검증** — 정리 모드를 먼저 만들고, 같은 질문을 REM 전후로 던져 답이 실제로 달라지는지 확인해요.
   - 끝 기준: 달라진 예시 3개를 기록. 달라지지 않으면 설계를 고친 뒤 넘어감
4. **수정 제안과 버전 관리** — 제안 카드, 적용, 되돌리기를 만들어요.
5. **REM 모드 2 + 모드 파일 구조** — 꿈 모드를 붙이고, 모둠원이 새 모드를 파일 하나로 추가할 수 있게 해요.
6. **REM 애니메이션과 디버그 수치** — 처리 중인 노드 강조, 통찰 도형 등장, 토큰·시간·오류 기록.
7. **전시용 정리** — 하루 이야기 입력, 관람객별 초기화 버튼, 시연 대본, 인터넷이 끊겼을 때 보여 줄 녹화 영상.

3단계가 이 프로젝트의 핵심 가설이에요. 여기서 'REM 후에도 별 차이가 없다'가 나오면 화면을 아무리 다듬어도 전시가 약해져요. 그래서 화면보다 먼저 시작하는 것도 고려해 볼 만한데, 오늘은 초안에 넣을 화면이 필요해서 1단계부터 해요.

## 위험 요소와 대응

가장 큰 위험은 'REM을 해도 AI가 별로 안 달라 보이는 것'이고, 그다음이 전시장에서의 이상한 입력과 인터넷 문제예요.

| 위험 | 일어나면 | 대응 |
| --- | --- | --- |
| REM 전후 차이가 작음 | 전시의 핵심이 안 보임 | 3단계에서 먼저 검증, 전후 같은 질문 비교 화면 준비 |
| 관람객의 장난·부적절한 입력 | 이상한 규칙이 인격에 들어감 | 자동 적용 금지, 제안 후 승인, 관람객별 초기화, 간단한 입력 필터 |
| 무료 API 한도 초과 | 시연 중 응답 멈춤 | 한도 미리 확인, REM은 한 번에 처리할 노드 수 제한, 유료 키 예산 검토 |
| 전시장 인터넷 불안정 | 모델 호출 실패 | 휴대폰 테더링 준비, 시연 녹화 영상 대비 |
| API 키 노출 | 남이 키를 써서 요금 발생 | 키는 서버 쪽 설정 파일에만, GitHub에 올리지 않기 |
| 뇌과학 설명 오류 | 발표 때 지적받음 | 2절의 논문 확인 후 발표 자료 작성 |
| 개발 경험 부족 | 오류를 못 고치고 멈춤 | 단계마다 작게 끝내기, 오류 메시지를 그대로 Claude Code에 전달 |

## 축제 전시 운영

관람객 한 명이 3\~5분 안에 '기억이 쌓이고, AI가 자고, 깨어나서 달라지는' 과정을 다 보는 것이 목표예요. 시간은 Claude의 예상이라 리허설로 확인해야 해요.

1. 초기화된 AI로 시작해요. 관람객은 하루 이야기를 쓰거나 AI와 4\~6번 채팅해요.
2. 같은 '확인 질문'(예: '나에 대해 어떻게 생각해?')을 한 번 던져 답을 기록해 둬요.
3. '잠들기'를 누르면 REM이 돌아가요. 노드가 하나씩 빛나고 통찰 도형이 생겨요.
4. 깨어난 뒤 수정 제안 카드를 같이 읽고, 관람객이 적용 여부를 골라요.
5. 확인 질문을 다시 던져 전후 답을 나란히 보여 줘요.
6. 다음 관람객을 위해 초기화해요.

모드 1과 모드 2를 같은 기억으로 각각 돌려 결과를 비교하는 화면을 두면, '정리하는 잠'과 '꿈꾸는 잠'의 차이를 설명하는 볼거리가 돼요.
