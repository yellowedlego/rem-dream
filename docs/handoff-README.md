# 꿈(REM) 시스템 — Claude Code 인수 자료

이 폴더는 꿈 시스템 동아리 프로젝트를 시작하기 위한 참고 자료예요.

## 들어 있는 것

- `README.md` — 이 파일. 작업 지시와 규칙
- `plan.md` — 기획서 (따로 내려받아 이 폴더에 넣을 것)
- `design-reference/Main.dc.html` — 전시 화면 · 깨어 있을 때 (왼쪽 대화, 오른쪽 기억 노드 좌표평면, 스크롤하면 노드가 대화 구간을 비춤)
- `design-reference/Rem.dc.html` — 전시 화면 · 꿈꾸는 중과 깨어난 뒤 수정 제안 카드 (예전 배치, 아직 새 배치로 안 바뀜)
- `design-reference/Debug.dc.html` — 디버그 화면 (로그, 수치, 인격 버전·되돌리기)
- `design-reference/screenshots/` — 위 화면 캡처 (있으면)

`.dc.html` 파일은 디자인 도구 전용 형식이라 브라우저에서 그대로 열리지 않아요. 코드로 읽어서 화면 구성과 상호작용 방식만 파악하세요.

## 작업 규칙 (꼭 지킬 것)

1. **프로토타입 디자인을 따르지 말고 새로 만들 것. 참고만 할 것.** 화면 배치와 상호작용 아이디어(대화를 비추는 노드, 수정 제안 카드, 디버그 항목)만 참고하고, 색·글꼴·세부 모양·코드 구조는 새로 정한다.
2. 범위는 `plan.md`의 로드맵 1단계만: 노드·통찰·인격 버전의 데이터 모양을 정하고, 가짜 노드 20개로 전시 화면(`/`)과 디버그 화면(`/debug`)을 띄운다.
3. 요청하지 않은 부분은 고치지 않는다.
4. 점검을 요청하면 고치지 말고 문제만 기록해서 보고한다. 수정은 승인받은 뒤 한꺼번에 한다.
5. 라이브러리를 고를 때는 Context7로 최신 문서를 확인한다.
6. API 키는 서버 쪽 설정 파일에만 두고, 저장소에 올리지 않는다 (`.gitignore`에 추가).
7. 화면을 만들면 Playwright로 스크린샷을 찍어 확인하고, 결과를 보여 준다.

## 핵심 개념 요약

- 노드 = {유저 입력, AI 답변} 한 쌍. 채팅 한 번에 노드 하나.
- 잠들기(REM) 중에는 입력을 막고, 별도 모델이 노드를 다시 읽어 통찰을 만든다.
  - 모드 1(정리): 노드 순서를 섞고, 앞에서 뽑은 통찰을 다음 노드를 읽을 때 맥락으로 넘긴다.
  - 모드 2(꿈): 무작위 노드 두 개를 짝지어 연결고리를 찾게 하고 온도를 높인다.
- 통찰을 모아 시스템 프롬프트(인격) 수정 제안을 만든다. 사람이 승인할 때만 새 버전으로 저장하고, 언제든 되돌릴 수 있다.
- 모델은 제미나이 Flash 계열 (정확한 모델명은 시작할 때 확인).
